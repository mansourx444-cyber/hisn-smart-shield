# ٦. النشر والوصول — ليجرب الجميع «حِصن»

## ٦.١ الرابط الدائم على Render (للجنة والمشاهدين)
المشروع جاهز للنشر: ملف `render.yaml` في المستودع فيه كل الإعدادات.

**خطوات أول مرة (٥ دقائق):**
1. افتح <https://render.com> ← **Get Started** ← سجّل الدخول بحساب **GitHub**.
2. **New +** ← **Blueprint** ← اختر المستودع `hisn-smart-shield` ← **Apply**.
3. انتظر حتى تصير الحالة **Live** (٢–٤ دقائق). الرابط يكون مثل: `https://hisn-smart-shield.onrender.com`

بعدها كل دمج على `main` ينشر تلقائيًا.

**الصفحات:**
| الرابط | ماذا يفتح |
|---|---|
| `/` | تطبيق «حِصن» (هاتف الضحية) |
| `/scammer` | هاتف المحتال |
| `/demo` | صفحة العرض: الهاتفان جنبًا إلى جنب |
| `/phones` | رمزا QR لربط هاتفين حقيقيين |
| `/partners` | بوابة الجهات |
| `/ai.html` | تقنيات الذكاء الاصطناعي في كل مرحلة |

> ⏱️ **ملاحظة الخطة المجانية:** الخدمة تنام بعد ١٥ دقيقة بدون زيارات، وأول فتح بعدها يأخذ قرابة دقيقة. **افتح الرابط قبل العرض بدقيقتين.**
> صفحة `/settings` (تعديل الأصوات) تعمل فقط من الكمبيوتر المحلي، والتسجيلات المرفقة في `voices/` تعمل على الرابط الدائم تلقائيًا.

### تجربة المحكّم بهاتفين من الرابط الدائم
1. افتح `/phones` على شاشة العرض.
2. **الهاتف الأول:** امسح الرمز الأول ← «الدخول بالهوية الرقمية» ← «تفعيل» ← يظهر **رمز الربط**.
3. اكتب رمز الربط في صفحة `/phones` ← يظهر الرمز الثاني.
4. **الهاتف الثاني:** امسحه ← يرتبط بالأول. أرسل رسالة أو اتصل.

### تجربة بهاتف واحد أو كمبيوتر
افتح `/demo` ← كل شي في صفحة واحدة.

## ٦.٢ الرابط المؤقت من الكمبيوتر (عرض حي بدون إنترنت للخادم)
في ويندوز: شغّل **`SmartShield-Phones`** من مجلد المشروع ← يفتح رابطًا آمنًا عبر Cloudflare ← صفحة `/phones` برمزين، والربط تلقائي بدون كتابة رمز.
- الرابط يتغير في كل تشغيل.
- لازم الكمبيوتر يبقى شغال طول العرض.
- للإيقاف: `SmartShield-Stop`.

## ٦.٣ التشغيل المحلي (للمطورين والمحكّمين)
```bash
git clone https://github.com/mansourx444-cyber/hisn-smart-shield.git
cd hisn-smart-shield
node server.js          # يحتاج Node.js 22 فقط — بدون npm install
# افتح http://localhost:3000/demo
npm test                # 54 اختبارًا للمحرك
```

## ٦.٤ ملاحظات تقنية
- **الميكروفون يحتاج HTTPS**: الرابط الدائم والمؤقت كلاهما HTTPS.
- **الاتصال الحي:** إذا كان الوسيط يحجز البث المتدفق، يتحول النظام تلقائيًا إلى استطلاع طويل (`public/live.js`).
- **صوت المكالمة بين شبكتين مختلفتين** (واي فاي + بيانات) قد يحتاج خادم TURN: `TURN_URL` / `TURN_USER` / `TURN_PASS`. التنبيه والتحليل يعملان حتى لو تعذّر الصوت.
- **هاتف المحتال:** يُفضّل أندرويد (Chrome) أو لابتوب لأن تحويل الكلام إلى نص فيهما أثبت.
- **المكالمات الهاتفية العادية** لا يمكن تحليلها من تطبيق ويب (قيود iOS و Android)، والعرض الحي يستخدم المكالمة داخل التطبيق.

## ٦.٥ قائمة التحقق قبل العرض
- [ ] الرابط الدائم مفتوح قبل دقيقتين (حتى يصحو).
- [ ] الهاتفان مشحونان، الصوت مرتفع، وضع عدم الإزعاج مفعّل.
- [ ] تجربة كاملة: رسالة ← تنبيه، مكالمة ← «عطني الرمز» ← تنبيه.
- [ ] الخطة البديلة جاهزة: `/demo` على الكمبيوتر + الفيديو.
